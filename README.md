# Práctica 3 - Entornos de Desarrollo

Práctica de introducción al uso de Git y GitHub en la asignatura de
**Entornos de Desarrollo**.

Esta actividad no se entrega. Su objetivo es practicar un flujo de trabajo
básico con repositorios, ramas, fusiones y colaboración mediante GitHub.

## Contenidos

Durante la práctica se trabajan los siguientes conceptos:

- Creación y configuración de un repositorio.
- Uso de Codespaces y comprobación de la identidad en Git.
- Ciclo básico de Git: `add` y `commit`.
- Uso del archivo `.gitignore`.
- Consulta del historial y uso de `diff`.
- Recuperación de cambios con `restore` y `revert`.
- Creación de ramas y fusión de cambios.
- Provocación y resolución de conflictos.
- Envío y recepción de cambios con `push` y `pull`.
- Creación de un Pull Request.
- Uso de etiquetas de versión.

## Plan de trabajo

| Fase        | Actividad                                                                              | Tiempo |
| ----------- | -------------------------------------------------------------------------------------- | -----: |
| Preparación | Pasos 1 y 2: crear el repositorio, abrir el Codespace y comprobar la identidad en Git. |  5 min |
| Parte 1     | Pasos 3 a 5: ciclo básico (`add`, `commit`) y `.gitignore`.                            | 10 min |
| Parte 2     | Pasos 6 a 8: historial, `diff`, `restore` y `revert`.                                  |  8 min |
| Parte 3     | Pasos 9 y 10: ramas y fusión.                                                          |  7 min |
| Parte 4     | Pasos 11 a 13: provocar y resolver un conflicto.                                       | 12 min |
| Parte 5     | Pasos 14 a 16: `push`, Pull Request, `pull` y etiqueta de versión.                     | 11 min |
| Cierre      | Paso 17: repaso, autoevaluación y detener el Codespace.                                |  7 min |

## Requisitos

- Una cuenta de GitHub.
- Acceso a GitHub Codespaces.
- Git instalado o disponible dentro del Codespace.

## Objetivo final

Al terminar la práctica, se debe comprender el flujo básico para trabajar con
Git de forma individual y colaborativa, manteniendo un historial de cambios
ordenado y resolviendo posibles conflictos entre ramas.
